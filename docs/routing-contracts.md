# Task 7 routing module handoff

## Public seams

- `routing/engine.ts`: `propose(task, snapshot, candidates, spend, signal, childContext?) -> Promise<Proposal>`. Default implementation calls the real `classifyRequest` and unchanged `decide`. `createEngine({ classify?, recordUsage? })` provides deterministic classifier and accounting seams. Inputs are privately copied before asynchronous work; key/endpoint environment selection is captured per evaluation. Supplied candidates must already be scoped/authenticated.
- `routing/intercept.ts`: `eligible(toolName, input)`, `applyDefaults(input, defaults, captured, current, signal?)`, and `LaunchRouter`. Construct once per runtime with owner/config, public bus/catalogue, optional classifier/usage/audit/warning callbacks. Call `handle({ toolName, toolCallId, input }, { owner, signal?, modelRegistry, spend, cwd?, isProjectTrusted?, ui? })` from a future public tool-call handler. The returned `HookOutcome` is router metadata, **not** a native hook return/block directive. That handler must await the service and return normally without launching anything.
- `LaunchRouter.snapshot` returns a copy. `update({ owner?, config?, enabled?, mode? })` advances generation, aborts all pending request controllers and resets discovery. Use it for owner/session replacement, reload and configuration changes (including budget changes); `dispose()` permanently disables the instance. Re-enabling does not revive old calls. No task/history cache is retained.
- `routing/modes.ts`: `defaultsFor`, `cheaperDecision`, `chooseDefaults`. Optional `SelectUI.select(title, options)` adapts the public select callback; expose it only when interactive UI is available.

## Native input semantics

Only immediate native `Agent` calls with nonempty string prompt/subagent_type and at least one `undefined` model/thinking field qualify. Truthy resume/schedule operations skip; empty-string placeholders qualify. Explicit `off`, `null`, empty string, false and invalid values are not repaired. Both explicit fields skip classification. Only still-undefined model/thinking fields are written in place; every unrelated option/object identity and the native prompt remain untouched. Model defaults are exact provider/id; thinking comes only from the chosen configured target pin, including `off`. Native code owns clamping and definition-first precedence. Entries label injected values **proposed**, not effective settings.

New short tasks are always classified without parent history/current-model/cache context. Agent identity (up to 1,000 characters) plus task is capped to 8,000 characters; truncation metadata concerns the classification copy only. Optional `childContext` is exclusively for a future explicitly correlated existing-child operation; launch handling never supplies it.

Discovery uses `TintinDiscovery` and the current public catalogue/bus. `DiscoveryStatus.epoch` is a monotonic runtime-local token returned with readiness; `onInvalidation((epoch) => void)` synchronously notifies observers and returns an idempotent unsubscriber. Observed schema/source fingerprint or compatibility changes, owner/generation replacement and explicit `reset()` advance the epoch and cancel stale probes. Successful unchanged-catalogue discovery keeps its token/cache; misses still retry. Post-ping inspection rechecks the captured epoch after the synchronous catalogue callback, before publishing any result: reentrant change-and-restore must not overwrite newer discovery state. Subscriber exceptions are contained. Each ready launch request binds the returned epoch. Invalidation aborts older bound request controllers, including completed discovery requests waiting on classification or confirmation, but not new unbound discovery requests. Notification only aborts; it never calls router update/reset. The final catalogue snapshot must match the request's epoch immediately before `applyDefaults`, independently of shared readiness or fingerprint equality: a change-and-restore cannot revive the old request. `dispose()` unsubscribes discovery notifications and aborts requests. Production scope uses `resolveSettingsScope` against the complete backend registry before candidate intersection. Public `getAvailable()` is the authenticated view, including an authoritative empty result. A `getAll()` fallback requires public synchronous `hasConfiguredAuth()` validation; otherwise candidates are omitted. Unknown scope, restricted-empty chains and missing auth/protocol fail open. Final scope/auth/catalogue validation runs again after classification and confirmation; generation/owner/mode/enabled/operation-signal and field omission are checked before mutation. Session-operation signal linkage does not imply exact per-tool cancellation fidelity.

Auto fills eligible defaults. Notify audits only. Confirm offers selected, an available scoped/authenticated lower-tier-chain choice if present, and keep; keep/cancel/unoffered values supply none. Cheaper choice retains its own configured thinking pin and independent decision metadata. Absent interactive select uses documented auto fallback (`confirm-unavailable-auto`); a throwing UI fails open instead.

## Counters, privacy and failure metadata

`recordUsage({ owner, toolCallId, requests: 1, status, usage? })` is called once per classifier evaluation independently of mode/application, including keep/preserved outcomes. `status` distinguishes classified from failed evaluations; `usage` is supplied only when reported. This is not retry/HTTP accounting and missing usage is not a fabricated zero. Missing key/ineligible calls perform no evaluation. No callback means `usage-unrecorded`; rejection means `usage-callback-failed`. Callback completion is not a durability receipt. **Task 8 must wire atomic persistent accounting**; this module never writes the old ledger.

Audit receives only normalized analysis/decision, session/tool identifiers, action and static reason/scope codes—not prompts, native options, config credentials or parent history. Audit/UI/warning errors are contained and reflected as degraded codes. Unknown scope diagnostics are allowlisted before audit. No raw tasks are written to disk. Task content is sent to the configured Jev endpoint when classification runs.

## Limits and verification

No production extension registration, commands, child controller, accounting store or second launcher is supplied. Task 12 must bind the service to actual public lifecycle/input/context callbacks and present discovery warnings (including Tintin installation/reload guidance). Task 11 owns any future bounded task retention/UI. Existing native fixtures established the independent host input-mutation contract; Task 7 tests compose the real client with fake fetch, scope/discovery adapters, policy and hook mutation. They do not establish production-entry/native-runtime integration or full router parity.

Focused/default execution remains explicit-path and sandbox-only. `scripts/isolated.sh routing` runs `test/routing`; default `test` includes it and still excludes opt-in native integration suites. The only shared-contract change makes `Proposal.analysis` optional for fail-open results and adds optional static reason/degraded metadata; no synthetic analysis is created on errors.

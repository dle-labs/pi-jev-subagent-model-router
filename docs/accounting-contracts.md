# Task 8: durable child accounting handoff

This supplies accounting services, not an observer, controller, extension entry or native support expansion. Tasks 9–12 must integrate the public lifetime/authorization and lifecycle seams. All changes remain uncommitted. No vendor or installed-package changes were made.

## APIs and trust boundary

- `state/money.ts`: `decimalUsd(number)`, `canonicalUsd(string)`, `addUsd(a,b)`, `cumulativeDelta(previous,observed)`. Admission preserves every digit of `Number.toString()`, expands exponents (including `5e-324`), and uses BigInt decimal arithmetic thereafter. Strings are bounded to 1,024 characters, exponent magnitude/scale to 400, and numeric projections must remain finite. Negative/invalid/nonfinite inputs reject before arithmetic. Zero is canonical `"0"`; decreasing/equal observations produce zero delta without resetting the high-water mark. This cannot recover upstream floating-point loss; only presentation rounds.
- `state/atomic.ts`: `withAtomicJson<T,R>(file, update, options?) -> Promise<R>`; `update(latest | undefined)` returns `{state, value}`. A missing file is the only absent-file case. Callers validate schema before updates. All accounting writes validate both loaded and resulting ledger state. Options include `signal`, `timeoutMs` (default 2,000; bounded 0–60,000) and `retryMs` (default 10; bounded 1–1,000). `before(owner-write|temp-write|rename)` and `afterRename()` are narrow local fault-injection seams, never runtime backend monkeypatches. Failures expose static `AtomicError.code` values, not raw filesystem/credential/task messages.
- `state/accounting.ts`: `AccountingStore(file, atomicOptions?)`, `registerOrigin(origin, association) -> Promise<accountingId>`, `observe(CostObservation) -> Promise<ObservationReceipt>`, `recordUsage(ClassifierUsage, eventId?)`, `createUsageRecorder(store)`, `rootOwnerId(canonicalProjectRoot, publicParentSessionId)`, `accountingId(namespace, origin)`. `cumulativeDelta` is also re-exported here. No cached in-memory watermark is advanced; every operation reloads under lock.

**Registration and observation are an explicit validated-correlation trust boundary, not ownership discovery.** The future observer must verify the public top-level launch/spawn correlation and current authorization *before every call*, including after reload or reassociation. Persisted associations are not ownership proof. The store does not consult backend records/private imports, personal directories, mutable parent costs, or current SDK owner/session/toolCallId/startedAt to infer a money identity. Caller-supplied project roots must already be canonical (e.g. public context with symlinks resolved); the helper checks absolute lexical canonicality but does not resolve symlinks or read settings. It combines root and public parent-session ID with `JSON.stringify([root, session])`.

Origin registration is a locked transaction, preceding costs. `AccountingId` is SHA256 of `JSON.stringify([namespace, backend, rootOwnerId, spawnToolCallId, childId])`. Namespace UUID is allocated once under the file lock. Immutable origins are projected to those four fields; no unknown extra metadata/prompts/keys are persisted. Re-registering a validated continuation with the same origin returns the same ID/high-water mark. An explicitly verified new spawn reusing a child ID gets another ID. Unknown original spawn/ambiguous replacement must never be registered using guesses: unresolved observation returns `unknown-attribution`, with no charge. Declining costs never invent a new lifetime.

Associations contain only current `{owner, child, generation}`. Lower generations and conflicting same-generation owner registration reject `stale-binding`; observations with mismatched owner/child/generation return `stale-binding`, without charging or changing the record's cost/pricing metadata. Higher-generation validated reassociation retains origin and watermark and adds `activity-uncovered`. Generation tokens must be monotonic for that lifetime across revalidation, not recreated from an unverified persisted binding.

Synthetic same-lifetime replacement/reassociation fixtures demonstrate this service's correlation contract. They are **not native lifecycle support claims**: accepted native support still excludes unavailable same-record SDK replacement and ownership transfer.

## File/schema and atomic invariant

The outer legacy `Ledger` remains version 1 with `days`, `months`, `jev`, `updatedAt` and numeric projections for unchanged policy pressure math. Its optional, independently versioned `accounting` envelope contains:

- `version: 1`, durable UUID `namespace`;
- immutable-origin records keyed by AccountingId with canonical `accountedUsd`, provenance (`record-lifetime`/`terminal-lifetime`), `top-level-including-descendants` aggregation scope, incomplete pricing reasons, static evidence codes, late/last-observed timestamp/model/reported-total metadata;
- separate current `associations`;
- `exactDays`/`exactMonths` buckets `{total: string, byModel: Record<string,string>}`;
- `evaluations` with request identity/status and reported/unavailable token-usage metadata;
- incomplete migration metadata (`legacy-rounded-loss-unrecoverable`).

One locked replacement resolves registered identity/current binding, adds only the exact positive cumulative delta to exact UTC day/month/model buckets, derives finite numeric projections, advances the watermark, and persists association/provenance/completeness metadata. Missing model uses `unknown-child-model`, never the parent model. Descendants have no separate charging API: the native top-level lifetime aggregate includes them. Both exact and numeric persisted inputs, namespace, hash/origin consistency, association linkage, counters and metadata validate before arithmetic; inconsistent or unsupported envelopes reject instead of migrating again.

Missing/invalid reported cost preserves watermark and buckets while persisting `cost-unavailable`/`cost-invalid`. A present zero (including serialized zero standing in for absent cost) remains `zero-unproven`, not verified free coverage. Zero-delta/terminal/replayed observations still union new pricing gaps; old observations cannot clear newer gaps or replace newer last-observed metadata. Mixed priced/unpriced native activity stays incomplete. Last reported metadata may decline; the durable accounted watermark cannot.

Tintin 0.19 provides **no verified complete-coverage evidence source**. Every record remains incomplete (`native-coverage-unverified`), even a finite positive total. A supplied `complete` flag/evidenceId is rejected as proof, records `unsupported-complete-proof`/`complete-proof-rejected`, and never clears gaps. Persisted complete records reject. No fixture-only production complete branch exists. Genuine free/complete acceptance is deferred until a public-contract coverage proof/frontier exists.

The explicit `CostObservation.at` is the attribution timestamp for each newly admitted delta (UTC-normalized bucket keys); `late` is preserved as last-observation metadata. Same timestamp partitions and aggregate agree on either side of midnight/month rollover. A late aggregate received after midnight is charged at its observation time; no historical equivalence is invented. Legacy `recordCost` accepts an optional timestamp, defaulting to current time.

Existing numeric bucket values migrate unchanged by `Number.toString()` admission once; their old rounded loss is unrecoverable and remains incomplete. Jev counters are preserved. Exact buckets are never reseeded after the envelope exists. For example legacy 0.3 plus newly admitted 0.00004 projects to 0.30004, with a 0.00004 by-model increment.

## Locking, failures and durability limits

The cooperating writers use the same canonical absolute file pathname and `<file>.lock` exclusive directory. Owner metadata includes UUID token, PID and timestamp, with private directory/file modes. No lock age/PID heuristic steals/removes another process's lock. Bounded monotonic-clock acquisition retry and abort reject; stale/crash locks degrade to `lock-timeout`, never fake success or empty history. Operators must externally establish that a crash lock is abandoned; there is no automatic recovery/stealing API.

Latest contents are loaded only under lock. A unique same-directory temporary is opened exclusively mode 0600, written, file-fsynced, closed and renamed. Cancellation checked before commit prevents publication. Rename is the commit point; abort or a throwing postcommit test hook after successful rename does not falsely claim rollback. Only this invocation's temporary/owned directory are cleaned in `finally`; lock device/inode and owner token are checked, unexpected/replaced ownership is left alone, and cleanup never recursively erases foreign contents. A failed own metadata write also cleans its identity-bound partial file. This is cooperating-writer safety, not protection against a hostile process replacing files between syscalls.

Crash temporaries are nonauthoritative and left untouched; intact ledger wins. Corrupt JSON, explicit malformed/null/nonfinite data, unsupported versions and unreadable existing files reject without replacement. Missing valid legacy fields may receive defaults without losing the fields that exist **only before an accounting envelope exists**. Envelope-bearing state requires its own complete `version`, `days`, `months`, `jev`, `updatedAt`, and all three safe-integer Jev counters; absence is corruption, not migration. Read validation and rejected store writes preserve the file bytes, including when a duplicate evaluation would otherwise acknowledge a retained event ID after counter loss. Legacy counter surplus is allowed: aggregate counters are not required to equal persisted evaluation sums. Temp-write/rename/commit failures preserve both durable buckets and watermark. Retrying after a simulated lost caller acknowledgement deduplicates against the durable watermark. Numeric projection overflow rejects the entire transaction. There is **no directory fsync or power-loss durability claim**. Postcommit cleanup failures may leave an owned lock and degrade later attempts; they cannot undo an acknowledged rename.

`core/budget.ts` legacy `loadLedger` now surfaces corruption/read failures. `saveLedger` is asynchronous and requires CAS against its exact loaded baseline (or an absent destination for a new untracked snapshot). Stale/untracked existing snapshots reject rather than overwriting newer accounting/counters. CAS is necessary but not sufficient: under the same lock, normalized previous/proposed state must also pass a compatibility transition guard. Existing accounting namespace, origins/records (including watermarks/proofs), associations, evaluations and migration history cannot be added, removed or edited by snapshot saves, even with internally valid rehashed replacement identities. Only `AccountingStore` owns that durable history. Every existing day/month/model bucket must remain with nondecreasing exact amounts, and each Jev counter must remain nondecreasing; sub-numeric-precision exact reductions also reject. Transition violations expose only static `invalid-ledger-transition` and preserve the original file bytes, without silently repairing caller or persisted corruption. New legacy in-memory additions retain exact buckets in a WeakMap without allocating any namespace; saving admits those buckets and generates the first namespace exactly once under lock. Both missing and existing envelope-free destinations reject a caller-assigned envelope before that allocation. Valid compatibility exact-cost additions, counter increments and repeated unchanged saves remain supported. `recordCost`/`recordJevUsage` remain explicitly nonproduction in-memory compatibility helpers: production integrations must use `AccountingStore`, not numeric-only additions followed by snapshot saves. Saving requires `await`; failed saves are not swallowed. `spendSnapshot` policy-pressure math and presentation formatting remain numeric and unchanged.

## Task 7 counter adapter

Pass `createUsageRecorder(store)` as Task 7's `recordUsage` service. Each actual callback invocation is one legitimate classifier evaluation, independent of notify, keep, application or classifier success. Missing usage increments requests but not measured tokens; an evaluation persists `usageStatus: unavailable`, so unchanged aggregate counters are not a fabricated measured zero. Reported integer token usage is validated before update; invalid/counter-overflow data rejects without increment.

`recordUsage` returns a committed/duplicate receipt and reported/unavailable status. Caller-supplied `eventId` enables delivery deduplication and conflicting identity reuse rejects. Owner/toolCallId alone does **not** deduplicate retries/multiple legitimate evaluations. Without explicit event ID a UUID identifies a distinct callback evaluation; Task 7 has no at-least-once delivery ID contract today. The adapter returns `Promise<void>` only after commit and propagates commit failure; the existing routing engine then exposes `usage-callback-failed` rather than claiming persistence. A missing counter consumer remains Task 7's `usage-unrecorded`. No token-usage-unavailable status is mislabelled commit failure.
